AI Assistant 平台技术白皮书

一、系统架构总览

AI Assistant 采用前后端分离的微服务架构。前端框架采用 Vue 3 + Vite 构建工具 + Pinia 状态管理。后端基于 Python FastAPI + Uvicorn 提供高性能 API 服务。数据库使用 PostgreSQL 16 + pgvector 扩展实现向量存储与语义检索，可选 ChromaDB 作为备选向量存储方案。Redis 7 用作缓存层，支持会话存储和速率限制。文件存储采用 MinIO 或 S3 兼容对象存储。整套系统支持水平扩展，可通过增加部署实例来提升并发处理能力。

二、部署环境要求

最低环境要求：Python 3.11 或更高版本，PostgreSQL 16+（需安装 pgvector 扩展），内存 8GB RAM，磁盘 50GB 可用空间，支持 Linux/Windows/macOS 操作系统。推荐使用 Docker Compose 一键部署。

三、支持的大语言模型

系统支持多种大语言模型并自动路由：DeepSeek 用于通用对话和复杂推理任务，默认模型为 deepseek-v4-pro；智谱 GLM-5.1 经过专门优化，适合文档总结和知识问答场景；OpenAI 兼容接口可作为备选方案（需要配置 openai_api_key）。每次对话回答都会附信息溯源来源标注，确保答案可追溯可验证。

四、嵌入模型与向量检索

嵌入模型：系统使用智谱 GLM Embedding-3 API 作为嵌入模型，向量维度为 1024 维。

两阶段混合检索策略：第一阶段（粗筛）基于向量相似度和 BM25 关键词匹配的混合检索，从知识库中召回 top_k=20 的候选文档片段。当首次检索置信度低于 0.35 时，系统自动触发 HyDE（假设性文档嵌入）策略，先让 LLM 基于原始问题生成一个假设性回答，然后将该回答文本进行二次编码检索，从而提高召回率。第二阶段（精排）使用 BAAI/bge-reranker-large 重排序模型对候选片段进行相关性重打分，最终保留 top_k=5 个最相关结果。重排序模型能有效提升检索结果的准确性，过滤掉不相关的噪声片段。

五、文档上传与处理

支持的文档格式：平台支持多种常见文档格式自动解析。PDF 文档使用 PyMuPDF 提取文本；Word 文档使用 python-docx 提取内容；PPT 演示逐页提取幻灯片；图片文件使用 PaddleOCR 文字识别；复杂排版 PDF 支持切换 Marker-PDF 智能解析。系统自动进行文档去重，使用 MD5 哈希值检测重复。

上传方式：用户可通过 Web 界面或 REST API 上传文档。Web 界面在文档管理页面点击上传按钮选择文件。API 方式为 POST /api/upload，支持 multipart/form-data 格式。上传后系统自动完成解析、分块、向量化入库，处理进度通过 SSE 实时推送。

六、前后端技术栈详情

前端框架 Vue 3，构建工具 Vite，状态管理 Pinia，后端框架 FastAPI，ASGI 服务器 Uvicorn，主数据库 PostgreSQL 16 + pgvector，缓存 Redis 7，对象存储 MinIO/S3。
