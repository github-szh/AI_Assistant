## 一、系统性能监控

**规范要求:**
- 记录每个 API 的响应时间 (ms)，支持 p50/p95/p99 百分位
- QPS 追踪 (1min/5min/15min 滚动窗口)
- SLA 计算 (月度/30天)
- LLM API 调用延迟 (TTFT, 总时间, 按 provider 分解)

**实际实现:**
- `src/monitoring/metrics.py` — `http_request_duration_seconds` Histogram (buckets: 0.01~30s) + `http_requests_total` Counter
- `src/api/middleware.py` — 记录每个请求的耗时 + 状态码
- `src/api/main.py:83` — `GET /metrics` 暴露 Prometheus 格式
- `src/monitoring/dashboard.py` — `GET /monitoring` 返回 HTTP 按端点计数
- LLM 调用延迟在 `record_llm_call(elapsed)` 参数中传入

**差距:** 无 SLA 计算模块，无 QPS 滚动窗口，无 TTFT 追踪，无百分位聚合

## 四、资源使用监控

**规范要求:**
- GPU 利用率/显存/温度 (pynvml)
- CPU 每核利用率
- 内存总量/已用/可用
- Redis 内存/驱逐率
- pgvector 查询延迟/索引大小/连接池
- 磁盘按类别统计 (文档/向量库/日志/模型)

**实际实现:**
- `src/monitoring/metrics.py` — `collect_resources()` 使用 psutil 采集 CPU%/内存/磁盘
- `main.py` 后台线程每 15s 采集
- `dashboard.py` `/monitoring` 直接调 psutil 实时读取

**差距:** 无 GPU 监控 (pynvml)，无 Redis/pgvector 监控，无按类别磁盘统计

## 七、成本管理

**规范要求:**
- 记录每次 LLM 调用的 prompt/completion/total tokens
- 按 provider/feature/user/session 分解
- 可配置的 provider 定价表
- 成本 = prompt_tokens × input_price + completion_tokens × output_price
- 日/周/月聚合
- 存储成本追踪 (向量库/文件/模型/日志)
- 预算告警 (50%/80%/100% 阈值)
- 每日异常检测 (spike > 3× 日均)

**实际实现:**
- `src/monitoring/metrics.py` — `_PRICES` 定价表 (8 个模型), `_estimate_cost()` 计算成本
- `record_llm_call()` — 每次 LLM 调用记录 (provider/model/tokens/cost/elapsed)
- `src/monitoring/storage.py` — SQLite 持久化 (llm_calls 表)
- `get_cost_summary()` — 按天/模型聚合
- `embeddings.py` — Embedding API 调用也计入成本
- `dashboard.py` — `/monitoring` 返回 llm_tokens/llm_costs/llm_call_count

**差距:**
- 无按 user/session/feature 分解
- 定价表硬编码在代码中，无可配置接口
- 无存储成本计算
- 无预算告警和异常检测
- 无每日聚合任务
