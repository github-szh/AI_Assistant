# 权限与多租户 — 实施计划

## Context

企业级知识库产品面向的是多团队、多部门的使用场景，而当前系统存在三个根本性问题：

1. **无租户隔离** — 所有用户共享数据。`t_document` 表虽有 `user_id` 字段但上传时未写入，`documents.py` 查询返回全部用户的文档。一个人上传的文档，全系统都能看到。

2. **无角色体系** — `t_user` 表无 `role` 字段，`get_current_user` 只返回 `{user_id, username}`。无法区分管理员和普通用户。

3. **无权限校验** — 所有已认证用户拥有完全相同的操作权限，上传、删除、查看等操作均无二次校验。

权限与多租户的解法：
- **多租户**：新增 `t_tenant` 表，所有数据表加 `tenant_id` 列，查询强制按租户过滤
- **RBAC**：4 级角色 × 17 项权限，角色-权限映射存放在 `t_role` / `t_permission` / `t_role_permission` 三张数据库表中，`permissions.py` 启动后首次校验时从数据库加载到内存缓存
- **管理后台**：租户创建/禁用、用户角色分配、系统设置查看

## 核心设计

### 多租户模型

```
                    ┌──────────────────┐
                    │    t_tenant      │
                    │  id / name / code│
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────────┐
              ▼              ▼                   ▼
      ┌────────────┐  ┌────────────┐  ┌──────────────────┐
      │   t_user   │  │ t_document │  │ t_session_info   │
      │ tenant_id  │  │ tenant_id  │  │ tenant_id         │
      │ role_id    │  │ user_id    │  │ user_id           │
      └───────┬────┘  └────────────┘  └──────────────────┘
              │
              ▼
      ┌──────────────────────────────────────┐
      │  data_documents (metadata_->>'tenant_id') │
      │  doc_summaries.tenant_id                  │
      │  chunk_contexts.tenant_id                 │
      └──────────────────────────────────────┘
              │
              ▼
      ┌──────────────────────────────────────┐
      │         RBAC 权限表                   │
      │  t_role  ←── t_role_permission ──→ t_permission │
      │  (角色名)    (多对多关联)       (权限标识)       │
      └──────────────────────────────────────┘
                     │
              t_user.role_id ──→ t_role.id
```

**策略**：共享表 + `tenant_id` 列（最轻量，单数据库实例即可支持数百租户）。权限映射存储在数据库而非代码中，支持运行时调整。

### 角色说明

| 角色 | 级别 | 适用场景 |
|------|------|----------|
| `super_admin` | 平台级 | 系统运维，管理所有租户和全局设置 |
| `tenant_admin` | 租户级 | 企业管理员，管理本租户成员、角色分配 |
| `editor` | 租户级 | 知识库运营人员，可上传/删除文档 |
| `viewer` | 租户级 | 普通用户，仅可对话和查看知识库 |

### 认证与租户上下文流

```
登录请求
  │
  ├── POST /auth/login → SQL JOIN t_role 获取角色名 → JWT payload 增加 role + tenant_id
  │
  ├── 前端存储到 localStorage + Pinia auth store
  │
  ├── 后续请求: Authorization: Bearer <token>
  │     │
  │     ├── get_current_user() 解码 → {user_id, username, role, tenant_id}
  │     │
  │     ├── require_permission("xxx") 从内存缓存查询 → 403 / 放行
  │     │
  │     └── 业务代码: WHERE tenant_id = current_user.tenant_id
```

### 2. `src/api/permissions.py` — 权限校验模块

**数据库驱动的权限加载**（首次校验时懒加载到内存）：

```python
_ROLE_PERMISSIONS_CACHE: dict[str, list[str]] | None = None

def _load_role_permissions() -> dict[str, list[str]]:
    """从数据库加载角色-权限映射"""
    conn = psycopg.connect(...)
    roles = conn.execute("SELECT id, name FROM t_role").fetchall()
    perms = conn.execute("SELECT id, code FROM t_permission").fetchall()
    rp = conn.execute("SELECT role_id, permission_id FROM t_role_permission").fetchall()
    conn.close()

    perm_map = {pid: code for pid, code in perms}
    result = {}
    rp_map: dict[int, list[int]] = {}
    for rid, pid in rp:
        rp_map.setdefault(rid, []).append(pid)
    for rid, rname in roles:
        result[rname] = [perm_map[pid] for pid in rp_map.get(rid, [])]
    return result

def _get_permissions() -> dict[str, list[str]]:
    global _ROLE_PERMISSIONS_CACHE
    if _ROLE_PERMISSIONS_CACHE is None:
        _ROLE_PERMISSIONS_CACHE = _load_role_permissions()
    return _ROLE_PERMISSIONS_CACHE
```

`check_permission()` 和 `require_permission()` 接口保持不变，只是内部从缓存查询而非硬编码字典。

**`require_permission()` — FastAPI Depends 兼容的权限校验器**：

```python
def require_permission(permission: str):
    def permission_dependency(user: dict = Depends(get_current_user)):
        if not check_permission(user.get("role", "viewer"), permission):
            raise HTTPException(403, f"权限不足，需要 {permission} 权限")
        return user
    return permission_dependency
```

**`can_manage_tenant()` — 跨租户操作判断**：

```python
def can_manage_tenant(user: dict, target_tenant_id: int) -> bool:
    role = user.get("role", "viewer")
    if role == "super_admin":
        return True  # 超级管理员可以操作所有租户
    return user.get("tenant_id") == target_tenant_id
```

def create_jwt(user_id: int, username: str, role: str = "viewer", tenant_id: int | None = None) -> str:

1. **数据库初始化**：执行 `init_all_tables.sql` + `seed_data.sql`，确认 11 张表 + 18 条权限 + 4 个角色 + 默认租户 + 4 个用户

3. **文档隔离验证**：
   - admin 上传文档 A → editor 登录看不到文档 A（不同租户）
   - 将 editor 改为和 admin 同一租户 → editor 能看到文档 A
4. **权限拦截验证**：
   - viewer 调用 `DELETE /documents/{id}` → 返回 403
   - viewer 调用 `POST /upload` → 返回 403

5. **管理后台**：tenant_admin 登录 → 看到用户管理 Tab；editor 登录 → 看不到"系统管理"链接
6. **RAG 隔离**：不同租户上传同名文档 → 检索结果互不干扰

## 整体数据流

```
注册流程:
  用户注册
    │
    ├── 有 tenant_code → 加入已有租户
    └── 无 tenant_code → 创建个人租户 (code: user_{uuid})
    │
    ▼
  INSERT t_user (role_id=(SELECT id FROM t_role WHERE name='viewer'), tenant_id=xxx)
    │
    ▼
  返回 JWT: { user_id, username, role, tenant_id }

请求流程:
  客户端请求
    │
    ├── Authorization: Bearer <jwt>
    │
    ├── get_current_user() 解码 → { user_id, username, role, tenant_id }
    │
    ├── require_permission("xxx") 从内存缓存校验
    │     └── role 不在映射表中 → 403
    │
    ├── 业务处理
    │     └── WHERE tenant_id = user.tenant_id
    │
    └── 返回数据（已按租户过滤）

前端流程:
  login → auth.login() → localStorage + Pinia
    │
  router.beforeEach → 检查 token + role
    │
  页面级别:
    ├── 侧栏 v-if="auth.isAdmin" → 显示管理入口
    ├── 上传按钮 v-if="canUpload" → 显示/隐藏
    └── 管理后台: 仅 super_admin/tenant_admin 可访问
```
