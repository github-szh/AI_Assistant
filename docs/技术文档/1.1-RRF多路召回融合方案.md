# RRF 多路召回融合 — ✅ 已完成 (2026-05-30)

## Context

当前 `retrieval.py` 使用 `VectorStoreQuery(mode="hybrid")` 把向量搜索和 BM25 融合交给 pgvector/llama_index 内部。但实际行为是 dense 优先去重、sparse 分数丢弃——不是真正的融合，BM25 精确命中关键词的信号被浪费。

改动目标：拆成两路独立召回 + RRF 融合，同时消除 `retrieve()` 和 `retrieve_with_rerank()` 之间 40 行重复代码。

## 修改文件：仅 `src/knowledge/retrieval.py`

### 改动 1：新增 `_bm25_search()` — BM25 独立搜索

绕过 llama_index，直连 PostgreSQL 做全文搜索。

```python
def _bm25_search(query_tokens: str, top_k: int) -> list[dict]:
    """BM25 关键词召回 — 绕过 llama_index 直连 PG 全文索引。"""
    import psycopg
    conn = psycopg.connect(settings.pg_dsn, connect_timeout=5)
    try:
        rows = conn.execute(
            """
            SELECT id, text, metadata_,
                   ts_rank(to_tsvector('simple', text), plainto_tsquery('simple', %s)) AS rank
            FROM data_documents
            WHERE to_tsvector('simple', text) @@ plainto_tsquery('simple', %s)
            ORDER BY rank DESC
            LIMIT %s
            """,
            [query_tokens, query_tokens, top_k],
        ).fetchall()
        return [
            {"node_id": r[0], "text": r[1], "metadata": r[2] or {}, "bm25_score": r[3]}
            for r in rows
        ]
    finally:
        conn.close()
```

关键细节：
- `query_tokens` 是 jieba 分词后的空格分隔文本（已经在 `_coarse_retrieve` 中准备好）
- `plainto_tsquery('simple', ...)` 自动转换为 `token1 & token2 & ...` 格式，无需手动拼 `&`
- `text_search_config='simple'` 无词干提取、无停用词，与写入侧一致
- `metadata_` 列在 psycopg3 中自动反序列化为 dict
- `node_id` = `data_documents.id` 列，对应 llama_index 的 `node.node_id`（`BaseNode.id_`）

### 改动 2：新增 `_rrf_fusion()` — RRF 分数融合

```python
def _rrf_fusion(
    dense_nodes: list,
    sparse_results: list[dict],
    k: int = 60,
    top_k: int = 20,
) -> list:
    """RRF (Reciprocal Rank Fusion): 综合两路排名。

    score(node) = Σ 1/(k + rank_i)，rank_i 从 0 开始。
    k=60 是经验最优值。
    """
    scores: dict[str, float] = {}
    node_map: dict[str, object] = {}

    # Dense 贡献
    for rank, node in enumerate(dense_nodes):
        nid = node.node_id
        scores[nid] = scores.get(nid, 0) + 1.0 / (k + rank + 1)
        node_map[nid] = node

    # Sparse 贡献
    for rank, row in enumerate(sparse_results):
        nid = row["node_id"]
        scores[nid] = scores.get(nid, 0) + 1.0 / (k + rank + 1)
        if nid not in node_map:
            # BM25 独有结果 — 从 DB 数据重建 TextNode
            from llama_index.core.schema import TextNode
            meta = row["metadata"]
            original_text = meta.get("original_text", row["text"])
            node = TextNode(
                text=row["text"],
                id_=nid,
                metadata={**meta, "original_text": original_text},
            )
            node_map[nid] = node

    # 按 RRF 分数降序
    sorted_ids = sorted(scores, key=lambda nid: scores[nid], reverse=True)
    result = []
    for nid in sorted_ids[:top_k]:
        node = node_map[nid]
        object.__setattr__(node, 'score', scores[nid])
        result.append(node)
    return result
```

关键细节：
- rank 从 0 开始，公式 `1/(k + rank + 1)` 等价于 rank 从 1 开始的 `1/(k + rank)`
- BM25-only 节点重建时，从 `metadata_` JSON 提取 `original_text`，保证 `_get_original_text()` 后续可用
- Dense 节点的 `node.node_id` 对应 PG 的 `id` 列，两者来自同一张表，UUID 一致

### 改动 3：新增 `_coarse_retrieve()` — 统一粗召回入口

抽取 `retrieve()` 和 `retrieve_with_rerank()` 的前 40 行重复代码：

```python
def _coarse_retrieve(self, query: str) -> list:
    """两路独立召回 + RRF 融合，返回排序后的节点列表。"""
    from llama_index.core.vector_stores.types import VectorStoreQuery
    from src.knowledge.embeddings import get_embedding_manager
    from src.knowledge.index_store import get_vector_store
    from src.knowledge.tokenizer import tokenize

    store = get_vector_store()
    embed_mgr = get_embedding_manager()

    # Embed & tokenize
    query_embedding = embed_mgr.encode_query(query)
    tokenized_query = tokenize(query)

    # 短查询加量
    qlen = len(query)
    coarse_k = (
        self.coarse_k + settings.retrieval_short_query_boost
        if qlen < settings.retrieval_short_query_len
        else self.coarse_k
    )

    # 路 1: 纯向量搜索
    q = VectorStoreQuery(
        query_embedding=query_embedding,
        similarity_top_k=coarse_k,
        mode="default",  # 仅向量，不做 hybrid
    )
    result = store.query(q)
    dense_nodes = result.nodes or []

    # 附加 similarity 分数
    if result.similarities:
        for node, score in zip(dense_nodes, result.similarities):
            if score is not None:
                object.__setattr__(node, 'score', score)

    if not dense_nodes:
        return []

    # 路 2: BM25 关键词搜索（PG 不可达时降级）
    try:
        sparse_results = _bm25_search(tokenized_query, top_k=coarse_k)
    except Exception:
        logger.debug("BM25 search unavailable, using vector-only")
        # PG 不可用 → 纯向量结果（节点已有 score）
        return dense_nodes[:coarse_k]

    if not sparse_results:
        return dense_nodes[:coarse_k]

    # RRF 融合
    fused = _rrf_fusion(dense_nodes, sparse_results, top_k=coarse_k)
    logger.debug(
        "RRF fusion: dense=%d + sparse=%d → fused=%d",
        len(dense_nodes), len(sparse_results), len(fused),
    )
    return fused
```

关键细节：
- `mode="default"`（非 "hybrid"）：只用向量搜索，BM25 走独立通道
- BM25 异常时自动降级为纯向量搜索，不影响可用性（ChromaDB fallback 场景）
- `dense_nodes` 如果是空列表，直接返回空，不尝试 BM25（如果向量搜不到，说明 PG 可能都挂了）

### 改动 4：简化 `retrieve()` 和 `retrieve_with_rerank()`

```python
def retrieve(self, query: str) -> list:
    fused_nodes = self._coarse_retrieve(query)
    if not fused_nodes:
        return []
    return fused_nodes[:self.fine_k]

def retrieve_with_rerank(self, query: str) -> list:
    fused_nodes = self._coarse_retrieve(query)
    if not fused_nodes:
        return []

    if settings.rerank_enabled:
        reranker = get_reranker()
        candidates = [_get_original_text(n) for n in fused_nodes]
        ranked = reranker.rerank(
            query, candidates,
            top_k=self.fine_k,
            min_score=settings.rerank_min_score,
        )
    else:
        return fused_nodes[:self.fine_k]

    # O(1) node lookup via text→[nodes] mapping
    from collections import defaultdict
    text_to_nodes = defaultdict(list)
    for node in fused_nodes:
        text_to_nodes[_get_original_text(node)].append(node)

    reranked_nodes = []
    for text, score in ranked:
        if text is None:
            node = fused_nodes[len(reranked_nodes)]
            object.__setattr__(node, 'score', 0.0)
            reranked_nodes.append(node)
            continue
        nodes = text_to_nodes.get(text)
        if nodes:
            node = nodes.pop(0)
            object.__setattr__(node, 'score', score)
            reranked_nodes.append(node)

    logger.debug("Reranker: %d → %d nodes", len(fused_nodes), len(reranked_nodes))
    return reranked_nodes
```

## 效果验证

使用 `verify_rrf.py` 对比三路检索结果（纯向量 / 纯 BM25 / RRF 融合）。

### 核心原理（一句话）

旧 hybrid 模式是"向量说了算，BM25 当备胎"。RRF 融合是"两路公平投票，都支持的权重更高"。

### 用 3 个 chunk 具体演示

查询"年假有几天？"，看 3 个有代表性的 chunk 在两路搜索中的表现：

**Chunk A："年休假制度"**

| | 排名 |
|:--|:--|
| 向量搜索 | #1 |
| BM25 搜索 | #1 |

旧 hybrid 处理：向量 #1，BM25 的 #1 排名**被忽略** → 最终 #1

RRF 处理：两路都确认它最重要 → RRF 分数 = 向量贡献 + BM25 贡献 → 最终 **#1**（分数比纯向量高，确认度更强）

**Chunk B："五险一金"**

| | 排名 |
|:--|:--|
| 向量搜索 | #8 |
| BM25 搜索 | #10 |

旧 hybrid 处理：取向量排名 → 最终 **#8**（BM25 的 #10 排名**被丢弃**）

RRF 处理：向量贡献 + BM25 贡献 → 两路"合力"推进 → 最终 **#3**

这是 RRF 的核心价值：**如果两路都认为它相关（即使各自排名都不高），合并后应该比只有一路支持的更可信。**

**Chunk C："钻井液论文"**

| | 排名 |
|:--|:--|
| 向量搜索 | 不在前 10 |
| BM25 搜索 | #2 |

旧 hybrid 处理：向量里没有 → **直接丢弃**，永远不出现

RRF 处理：BM25 独自给了它分数 → 进入前 10，但排在中游（因为没有向量加分）

这意味着：**如果你搜"漏失速度"，向量可能不理解这个专业术语，但 BM25 能精确命中——旧 hybrid 会丢弃 BM25 找到的精确匹配，RRF 会保留它。**

### 三路重叠分析

以查询"年假有几天？"为例：

```
向量 top-10:    10 条
BM25  top-10:   10 条
两路重合:        3 条  ← RRF 加权提升
仅向量命中:      7 条
仅 BM25 命中:    7 条  ← 旧 hybrid 会丢弃这些
```

### 具体 chunk 排名变化

| RRF 排名 | 内容 | 向量排名 | BM25 排名 | 标记 | 说明 |
|:--|:--|:--|:--|:--|:--|
| #1 | 年休假制度 | #1 | #1 | B | 两路都排第一，RRF 最高分 |
| #2 | 旷工解除合同 | #4 | #3 | B | 两路都支持，从 #4 提升到 #2 |
| #3 | 五险一金 | #8 | #10 | B | 两路都支持，从 #8 跳到 #3 |
| #4 | 总则 | #2 | — | D | 纯向量结果，保留 |
| #5 | 钻井液论文 | — | #2 | S | **旧 hybrid 会丢弃！** |
| #6 | 旷工处理 | #3 | — | D | 纯向量结果 |
| #7 | 简历 | — | #4 | S | **旧 hybrid 会丢弃！** |

标记含义：**B** = 两路都有，**D** = 仅向量有，**S** = 仅 BM25 有（旧 hybrid 会直接丢弃）

### 三个直观验证点

**1. 两路命中者被加权提升（标记 B）**

"五险一金" chunk 在向量排 #8、BM25 排 #10，两路各自排名都不高。但 RRF 给它加了两份贡献分，最终排到 #3。核心理由：**两路独立算法都认为它相关，合并后比只有一路支持的更可信。**

**2. BM25 独有结果被保留（标记 S）**

"钻井液论文" chunk 在向量 top-10 中完全不存在（语义相差太远），但 BM25 排到 #2（精确命中关键词"年"等）。旧 hybrid 模式下它会被直接丢弃。RRF 保留它并给了 BM25 排名对应的分数。如果后续 reranker 判定它不相关，自然会被过滤掉——但至少不会在粗召回阶段就被丢弃。

**3. 标记 B 的结果 RRF 分明显高于 D/S**

两路重合的 3 条 RRF 分在 0.029-0.033，单路结果的 RRF 分在 0.015-0.016，区分度约 2 倍。这确保了两路共识的候选排在前面。
