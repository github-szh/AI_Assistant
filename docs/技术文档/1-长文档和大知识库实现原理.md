# 长文档和大知识库 — 实现原理

> 基于项目现有架构（pgvector + llama_index + BGE-reranker-v2-m3），
> 三项核心优化的详细实现方案。

---

## 当前架构速览

```
查询 → embedding → VectorStoreQuery(mode="hybrid") → pgvector → 粗排 top-20
                                                                    │
                                                                    ▼
                                                           Reranker 精排 → top-5
                                                                    │
                                                                    ▼
                                                            组装 context → LLM
```

存在的问题：

| 问题 | 影响 |
|:--|:--|
| hybrid 模式内部是 dense 优先去重，sparse 分数被丢弃 | BM25 精确命中关键词的信号丢失 |
| chunk 是孤立的 1024 字符片段，检索命中后 LLM 看不到上下文 | 答案不完整，丢失跨 chunk 信息 |
| 文档摘要已生成但未索引，大库场景下全库检索噪声大 | 检索精度随文档数量增加而下降 |

---

## 第 1 项：RRF 多路召回融合

### 解决什么问题

当前 `mode="hybrid"` 把向量搜索和 BM25 搜索的融合交给了 pgvector/llama_index 内部。
LlamaIndex 的 `PGVectorStore._hybrid_query()` 实际行为是：

```
两条独立 SQL → 拼接 → dense 优先去重 → sparse 的分数被丢弃
```

这不是融合，是"dense 优先，sparse 当备胎"：

- 一个 chunk 在向量搜索排第 15，在 BM25 排第 1（精确命中关键词）→ 最终只携带向量分数，BM25 第一名信号被丢弃
- 一个 chunk 只在 BM25 中出现（关键词精确匹配，但向量相似度低于 top_k 阈值）→ 被去重丢弃，永远不出现在结果里

**真实场景**：

```
知识库 100 篇文档，用户问："2024年Q3的OKR完成率是多少？"

向量搜索 top-5：
  1. "本季度目标达成率85%，较上季度提升12%" (0.78) ← 语义相似但不精确
  2. "OKR考核制度实施细则..." (0.72)
  3. "Q3财务报表，营收1.2亿..." (0.68)
  ...

BM25 搜索 top-5：
  1. "2024年Q3 OKR完成率统计表：部门A 90%，部门B 82%..." ← 精确命中！
  ...

当前 hybrid：BM25 #1 如果没出现在向量 top-20 里就被丢弃
RRF 融合后：BM25 #1 同时拿到两路排名分，总分最高排第一
```

### 实现方案

核心思路：把一路 hybrid 查询拆成两路独立查询 + RRF 融合。
同时重构 `retrieve()` 和 `retrieve_with_rerank()` 消除重复代码。

#### 新增 BM25 独立搜索

pgvector 的 `PGVectorStore` 不支持纯 sparse 查询，需绕过 llama_index 直接用 psycopg：

```python
# src/knowledge/retrieval.py 新增

def _bm25_search(query_tokens: str, top_k: int) -> list[dict]:
    """直接用 PostgreSQL 全文搜索做 BM25 召回。"""
    import psycopg
    # jieba 分词结果转 tsquery: "word1 & word2 & word3"
    tsquery = " & ".join(query_tokens.split())

    conn = psycopg.connect(settings.pg_dsn, connect_timeout=5)
    try:
        rows = conn.execute(
            """
            SELECT node_id, text, metadata_,
                   ts_rank(to_tsvector('simple', text), to_tsquery('simple', %s)) AS rank
            FROM data_documents
            WHERE to_tsvector('simple', text) @@ to_tsquery('simple', %s)
            ORDER BY rank DESC
            LIMIT %s
            """,
            [tsquery, tsquery, top_k],
        ).fetchall()
        return [
            {"node_id": r[0], "text": r[1], "metadata": r[2], "bm25_score": r[3]}
            for r in rows
        ]
    finally:
        conn.close()
```

说明：`node.text` 已经是 jieba 分词后的空格分隔文本，`to_tsvector('simple', text)` 按空格切分即可。

#### RRF 融合函数

```python
def _rrf_fusion(
    dense_results: list,
    dense_scores: list[float],
    sparse_results: list,
    k: int = 60,
    top_k: int = 20,
) -> list:
    """Reciprocal Rank Fusion: 综合两路排名的分数。

    RRF 公式: score(node) = Σ 1/(k + rank_i)
    其中 rank_i 是 node 在第 i 路召回中的排名（从 1 开始）。
    k=60 是经验最优值，减小 k 让排名差异更显著。
    """
    scores: dict[str, float] = {}
    node_map: dict[str, object] = {}

    # Dense 贡献
    for rank, (node, score) in enumerate(zip(dense_results, dense_scores)):
        node_id = node.node_id
        scores[node_id] = scores.get(node_id, 0) + 1.0 / (k + rank + 1)
        node_map[node_id] = node

    # Sparse 贡献
    for rank, row in enumerate(sparse_results):
        node_id = row["node_id"]
        scores[node_id] = scores.get(node_id, 0) + 1.0 / (k + rank + 1)
        if node_id not in node_map:
            from llama_index.core.schema import TextNode
            node = TextNode(text=row["text"], metadata=row["metadata"], id_=node_id)
            node_map[node_id] = node

    # 按 RRF 分数降序
    sorted_ids = sorted(scores, key=lambda nid: scores[nid], reverse=True)
    result = []
    for nid in sorted_ids[:top_k]:
        node = node_map[nid]
        object.__setattr__(node, 'score', scores[nid])
        result.append(node)
    return result
```

#### 抽取公共粗召回方法

当前 `retrieve()`（line 34-74）和 `retrieve_with_rerank()`（line 76-142）的前半段完全重复：
embedding + tokenize + 短查询 boost + 构建 VectorStoreQuery。

抽取 `_coarse_retrieve()` 消除重复：

```python
def _coarse_retrieve(self, query: str) -> tuple[list, list[float]]:
    """两路独立召回 + RRF 融合，返回 (nodes, scores)。"""
    embed_mgr = get_embedding_manager()
    query_embedding = embed_mgr.encode_query(query)

    tokenized_query = tokenize(query)
    qlen = len(query)
    coarse_k = self.coarse_k + settings.retrieval_short_query_boost \
        if qlen < settings.retrieval_short_query_len else self.coarse_k

    # 路 1: 纯向量搜索
    q = VectorStoreQuery(
        query_embedding=query_embedding,
        similarity_top_k=coarse_k,
        mode="default",  # 仅向量，不做 hybrid
    )
    result = store.query(q)
    dense_nodes = result.nodes or []
    dense_scores = result.similarities or [0.0] * len(dense_nodes)

    # 路 2: BM25 关键词搜索
    sparse_results = _bm25_search(tokenized_query, top_k=coarse_k)

    # RRF 融合
    fused = _rrf_fusion(dense_nodes, dense_scores, sparse_results, top_k=coarse_k)
    return fused
```

`retrieve()` 和 `retrieve_with_rerank()` 简化为调用 `_coarse_retrieve()` 再取 top-k / 精排。

#### ChromaDB 降级

BM25 搜索依赖 PG 全文索引，ChromaDB fallback 下不可用。
在 `_coarse_retrieve()` 中判断：如果 PG 不可达，降级为纯向量搜索。

## 第 2 项：Sentence Window Retrieval（句子窗口检索）

### 解决什么问题

当前一个 50 页的 PDF 被切成 ~80 个 1024 字符的 chunk，每个是孤立的。
检索命中 chunk #37 和 chunk #62 时，LLM 看到的是两段中断的文本片段。

但 chunk 边界不等于语义边界——"年假申请条件"在 chunk #36，
"申请流程"在 chunk #37，"审批权限"在 chunk #38，
检索只召回 #37，丢失了关键上下文。

**Sentence Window 解法**：用小粒度做索引（精准检索），用大窗口做上下文（喂 LLM）。

```
┌─────────────────────────────────────────────┐
│  文档原文（连续的）                            │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐        │
│  │ sent1│ │ sent2│ │ sent3│ │ sent4│ ...    │  ← 索引层（小粒度）
│  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘        │
│     │        │        │        │             │
│  ┌──┴────────┴────────┴────────┴──────┐      │
│  │       window（前后各扩展 N 句）       │      │  ← 上下文层（大窗口）
│  └────────────────────────────────────┘      │
└─────────────────────────────────────────────┘

检索：query → 命中 sent2（0.82）、sent7（0.75）
展开：sent2 → 前后各扩 5 句 → 完整段落
      sent7 → 前后各扩 5 句 → 完整段落
去重合并 → 喂 LLM
```

**对比效果**：

```
没有 Sentence Window：
  LLM 收到: "年假需提前一周申请，经部门主管审批。"
  LLM 答: "提前一周向主管申请即可。"  ← 不完整

有 Sentence Window：
  LLM 收到: "公司规定员工享有带薪年假...
            年假需提前一周申请，经部门主管审批后方可使用。
            未休完的年假可结转至下一年度，但最多不超过5天。"
  LLM 答: "需提前一周向主管申请，最多结转到下一年度5天。"  ← 完整准确
```

### 实现方案

采用"父子 chunk"模式（比滑动窗口更简洁，兼容现有架构）：

```
父 chunk（~1024 字符，和现在一样）→ 给 LLM 看，存入 PG 普通表
子 chunk（~200 字符，取父 chunk 内的句子组）→ 做索引，存入向量库
子 chunk 的 metadata 存 parent_id → 检索后展开
```

#### Chunker 改造

```python
# src/parsing/chunker.py

@dataclass
class ChunkResult:
    index_chunks: list[ParsedDocument]    # 子 chunk（embed + 检索）
    context_chunks: list[ParsedDocument]  # 父 chunk（喂 LLM）
    index_to_parent: dict[int, int]       # 子 chunk i → 父 chunk j

def _sentence_split_with_parents(self, text: str,
                                   sentences_per_child: int = 3,
                                   sentences_per_parent: int = 15) -> ChunkResult:
    """句子级父子 chunk 拆分。"""
    sentences = re.split(r"(?<=[。！？.!?\n])\s*", text)
    sentences = [s.strip() for s in sentences if s.strip()]

    children = []
    parents = []
    child_to_parent = {}

    # 子 chunk: 每 3 句一组
    for i in range(0, len(sentences), sentences_per_child):
        child_text = "".join(sentences[i:i + sentences_per_child])
        children.append(child_text)

    # 父 chunk: 每 15 句一组，覆盖其子 chunk
    parent_idx = 0
    for i in range(0, len(sentences), sentences_per_parent):
        parent_text = "".join(sentences[i:i + sentences_per_parent])
        parents.append(parent_text)
        # 映射：该父 chunk 覆盖的所有子 chunk
        child_start = i // sentences_per_child
        child_end = (i + sentences_per_parent) // sentences_per_child
        for ci in range(child_start, min(child_end, len(children))):
            child_to_parent[ci] = parent_idx
        parent_idx += 1

    return ChunkResult(children, parents, child_to_parent)
```

```python
# src/knowledge/retrieval.py

def _expand_to_parents(self, child_nodes: list) -> list:
    """子节点 → 查父节点 → 去重返回。"""
    parent_ids = list(dict.fromkeys([
        n.metadata.get("parent_id") for n in child_nodes
        if n.metadata.get("parent_id")
    ]))

    if not parent_ids:
        return child_nodes  # 降级

    # 批量查 PG
    parents = _fetch_parent_contexts(parent_ids)  # SELECT * FROM chunk_contexts WHERE parent_id IN (...)

    # 重建结果，保留子节点的 score
    result = []
    seen = set()
    for node in child_nodes:
        pid = node.metadata.get("parent_id")
        if pid and pid not in seen:
            seen.add(pid)
            if pid in parents:
                parent_node = parents[pid]
                object.__setattr__(parent_node, 'score', getattr(node, 'score', 0))
                result.append(parent_node)
    return result
```

## 第 3 项：文档摘要索引（两级检索）

### 解决什么问题

**问题 1：大库场景下的检索稀释**

当知识库有 200 篇文档、~8000 个 chunk 时，一次检索要在 8000 个向量里找 top-20。
其中 180 篇无关文档的 chunk 仍参与排序——不仅浪费算力，更造成噪声干扰：

```
用户问: "病假需要提供什么证明？"
知识库: 200 篇（HR制度 20篇 + 技术文档 150篇 + 财务报告 30篇）

向量检索 top-20 中:
  HR chunks: 8 个   ← 仅 40% 相关
  技术 chunks: 7 个  ← "健康检查"、"异常处理"语义上接近"病"
  财务 chunks: 5 个  ← 完全无关

Reranker 精排后 top-5:
  HR 3 个 + 技术 2 个  ← 仍有噪声混入
```

**问题 2：和 doc_ids 过滤互补**

外部 doc_ids 过滤需要用户手动指定文档，用户通常不知道文档 ID。
文档摘要索引提供了自动化的"先选文档，再搜内容"——不需要用户干预。

**两级检索的解决方式**：

```
查询: "病假需要提供什么证明？"

第一层（文档摘要索引，200 条摘要向量）：
  query embed → 搜 200 条摘要 → top-3 相关文档：
    1. "员工病假管理制度 v3.0.docx" (0.82) ← 高度相关
    2. "员工手册-福利篇.pdf"         (0.71)
    3. "考勤与请假流程.docx"         (0.68)

第二层（chunk 索引，仅搜这 3 篇文档的 ~120 个 chunks）：
  query embed + MetadataFilters(doc_id IN [A, B, C]) → top-20
  候选集从 8000 收窄到 120，100% 来自相关文档

Reranker 精排 → 5 条高质量 context → LLM
```

精度提升：候选集从 8000 收窄到 120，噪声从 60% 降到趋近于 0。

```python
def _search_summaries(query_embedding: list[float], top_k: int = 3) -> list[dict]:
    """第一层：搜文档摘要，返回相关文档 ID 列表。"""
    conn = psycopg.connect(settings.pg_dsn)
    try:
        rows = conn.execute(
            """
            SELECT doc_id, summary, filename, chunk_count,
                   1 - (embedding <=> %s::vector) AS similarity
            FROM doc_summaries
            ORDER BY embedding <=> %s::vector
            LIMIT %s

            {"doc_id": r[0], "summary": r[1], "filename": r[2],
             "chunk_count": r[3], "similarity": r[4]}
            for r in rows
        ]
    finally:
        conn.close()
```

在 `query_engine.py` 的 `_retrieve()` 中加入两级检索分支：

```python
def _retrieve(self, question: str, top_k: int, doc_ids: list[str] | None = None):
    """两级检索 + 降级策略。"""

    # 如果外部指定了 doc_ids，直接过滤检索（跳过第一层）
    if doc_ids:
        return self._filtered_retrieve(question, top_k, doc_ids)

    # 如果文档数少，全库检索（跳过低价值的第一层）
    doc_count = _count_documents()
    if doc_count < settings.two_stage_min_docs:  # 默认 10
        return self._single_stage_retrieve(question, top_k)

    # 两级检索
    query_emb = embed_mgr.encode_query(question)
    relevant_docs = _search_summaries(query_emb, top_k=3)

    if not relevant_docs:
        return {"nodes": [], "sources": [], "context": ""}

    target_ids = [d["doc_id"] for d in relevant_docs]
    return self._filtered_retrieve(question, top_k, target_ids)
```

## 三项的依赖关系

```
第 1 项 (RRF 融合)
  │
  ├──→ _coarse_retrieve() 成为统一底座
  │
  ├──→ 第 2 项 (Sentence Window) 在 _coarse_retrieve() 基础上加 _expand_to_parents()
  │
  └──→ 第 3 项 (两级检索) 的 Level 2 需要 MetadataFilters
        RRF 的 _coarse_retrieve() 也需要支持 doc_ids 过滤
        两级检索推动 doc_ids 链路补完
```

推荐实施顺序：**1 → 2 → 3**。先建好稳定的融合检索底座，再往上搭窗口展开和两级索引。

## 实施后的整体架构

```
查询
  │
  ├── [文档摘要索引] 第一层: 搜摘要 → 确定目标文档 top-3
  │
  ├── [RRF 融合] 第二层: 在目标文档内
  │     ├── 向量搜索 (cosine similarity) ─────┐
  │     └── BM25 搜索 (ts_rank) ───────────────┤
  │                                            ▼
  │                              RRF 融合 → 粗排 top-20
  │
  ├── [Sentence Window] 展开: 子节点 → 父节点 → 去重
  │
  ├── [Reranker] 精排: bge-reranker-v2-m3 → top-5
  │
  └── 组装 context → LLM 生成
```
