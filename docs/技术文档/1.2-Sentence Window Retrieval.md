# Sentence Window Retrieval — 实施计划

## Context

当前 chunk 是孤立的 1024 字符片段，检索命中后 LLM 看不到前后文。比如"年假申请条件"在 chunk #36、"申请流程"在 #37、"审批权限"在 #38——检索只召回 #37 时，LLM 收到的是一段中断文本，丢失了条件、权限等关键上下文。

解决思路：用小粒度句子组做索引（精准检索），命中后展开到大窗口父 chunk（完整上下文喂 LLM）。

## 核心设计：父子 Chunk 模式

```
父 chunk（~1024 字符，15 句）→ 喂 LLM，存入 PG 普通表 chunk_contexts
子 chunk（~200 字符，3 句）  → 做索引，embed 后存入向量库 data_documents
子 chunk.metadata.parent_id → 检索后查 PG 展开到父 chunk
```

检索流程：
```
_coarse_retrieve() → 子节点（RRF 融合）
  ↓
_expand_to_parents() → 父节点（去重，继承子节点分数）
  ↓
reranker / LLM（拿到完整段落上下文）
```

## 修改文件

### 1. `src/parsing/chunker.py`

**新增 ChunkResult 数据结构：**

```python
@dataclass
class ChunkResult:
    index_chunks: list[ParsedDocument]    # 子 chunk（embed + 检索）
    context_chunks: list[ParsedDocument]  # 父 chunk（喂 LLM）
    index_to_parent: dict[int, int]       # 子 chunk i → 父 chunk j
```

**Chunker 构造函数新增参数：**

```python
def __init__(self, ..., sentence_window: bool = False):
    self.sentence_window = sentence_window
```

**新增方法 `chunk_with_windows()`**（保留原 `chunk()` 不变）：

- 仅对 `sentence` 和 `recursive` 策略生效
- `sentence`：先拆句子 → 3 句一组（子 chunk）→ 15 句一组（父 chunk）→ 建立映射
- `recursive`：段落级（子 chunk）→ 多段组合（父 chunk）
- `fixed_size` 和 `markdown_header`：降级为普通 chunk（子=父）

**关键参数**：`sentences_per_child=3`、`sentences_per_parent=15`（类常量，不暴露到 config）

**修改 `retrieve()` 和 `retrieve_with_rerank()`**：

```python
def retrieve(self, query: str) -> list:
    fused_nodes = self._coarse_retrieve(query)
    if not fused_nodes:
        return []
    expanded = _expand_to_parents(fused_nodes)     # ← 新增
    return expanded[:self.fine_k]

def retrieve_with_rerank(self, query: str) -> list:

    if not fused_nodes:
        return []

    # ... 后续 reranker 逻辑不变
```

**关键**：展开必须在 reranker 之前执行，这样 reranker 看到的是父 chunk 的完整文本。

```python
chunker = Chunker(
    strategy=strategy or settings.chunk_strategy,
    chunk_size=settings.chunk_size,
    chunk_overlap=settings.chunk_overlap,
    sentence_window=sentence_window or settings.sentence_window_enabled,

if chunker.sentence_window:
    result = chunker.chunk_with_windows(parsed)

    ingest_documents(chunks, doc_id=doc_id, filename=filename)
```

## 效果验证

### 一句话版

检索用"小碎片"更精准，但给 LLM 看的时候换成"大段落"让答案更完整。

### 以查询"请假需要什么条件？"为例

**第一步：检索找到 10 个"小碎片"（子 chunk，每 3 句一组）**

```
碎片1 (25字): "经部门负责人批准后方可休假。事假为无薪假。第九条。"
碎片2 (31字): "公司可安排岗位调整或协商解除合同。第八条。事假须提前1天申请。"
碎片3 (32字): "离职时未休年假按日工资折算。第六条。病假需提供医院开具的病假条。"
碎片4 (34字): "入职满20年可享受15天年假。第三条。年假需提前一周向部门主管申请。"
碎片5 (23字): "丧假为1-3天。根据亲属关系远近确定具体天数。"
```

每个碎片只有 20-30 字，信息残缺。比如碎片 1 只说了"事假须提前 1 天申请"，但没说是向谁申请。

**第二步：展开到 3 个"大段落"（父 chunk）**

系统发现碎片 1、2、3 都指向同一个父 chunk，碎片 4 指向另一个，碎片 5 指向第三个。去重后变成 3 个父 chunk：

```
大段落1 (143字):
"离职时未休年假按日工资折算。第六条。病假需提供医院开具的病假条。
 病假工资按最低工资标准80%发放。第七条。连续病假超过30天。
 公司可安排岗位调整或协商解除合同。第八条。事假须提前1天申请。
 经部门负责人批准后方可休假。事假为无薪假。第九条。婚假为3天。"

大段落2 (148字):
"第一条。公司规定员工享有带薪年假。年假天数根据工龄计算。
 第二条。入职满1年可享受5天年假。入职满10年可享受10天年假。
 入职满20年可享受15天年假。第三条。年假需提前一周向部门主管申请。
 经主管审批后方可使用。第四条。未休完的年假可结转至下一年度。"

大段落3 (23字):
"丧假为1-3天。根据亲属关系远近确定具体天数。"
```

**第三步：对比**

| | 给 LLM 看的内容 | 效果 |
|:--|:--|:--|
| 没有 Sentence Window | 碎片 1（25 字）："经部门负责人批准后方可休假。事假为无薪假。第九条。" | LLM 只看到一个孤立的句子 |
| 有 Sentence Window | 大段落 1（143 字）：包含事假、病假、婚假的完整规定 | LLM 看到完整段落，能回答所有请假类型 |

**数字总结**

```
10 个碎片 ──去重合并──→ 3 个大段落
  25字/个                   143字/个
  精准检索用                 完整上下文喂 LLM
```

核心逻辑：**搜的时候用小碎片（精准），答的时候用大段落（完整）。**
