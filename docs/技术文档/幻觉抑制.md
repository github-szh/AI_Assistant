# 幻觉抑制与事实校验 — 方案与实施

> 日期: 2026-05-31
> 状态: P0 + P1 已实施

---

## 背景

当前 RAG 系统已有多层幻觉抑制基础：

| 已有机制 | 做了什么 | 局限 |
|:--|:--|:--|
| Prompt 约束 | "禁止凭空编造"、"参考资料不足以回答时说明" | 全靠 LLM 自觉 |
| 来源标注 | 末尾附 `📚 来源：[1] 文件名` | 只标注 chunk，不校验内容 |
| Reranker 精排 | Cross-encoder 提高 top-5 chunk 精度 | 不保证 LLM 正确引用 |
| 前端拒绝检测 | 检测系统错误关键词后 fallback | 只拦截系统错误 |

**核心缺口**：没有机制校验"LLM 答案是否能从检索到的 chunk 中推出"。

---

## 方案选择

| 层级 | 方案 | 额外延迟 | 效果 | 状态 |
|:--|:--|:--|:--|:--|
| P0 | Prompt 逐句引用强制 | 0 | 幻觉减少 30-50% | ✅ 已实施 |
| P1 | 置信度标记（低/中/高）| 0 | 用户可判断可信度 | ✅ 已实施 |
| P2 | NLI 事实校验（复用 Reranker 子进程）| +2-5s/条 | 幻觉检测率 ~80% | 待评估 |

选择 P0 + P1：零延迟，高风险收益比。

---

## P0: Prompt 逐句引用强制

### 原理

旧 prompt 只要求在末尾列出出处——LLM 可以先生成答案，再事后匹配来源。这不能抑制生成过程中的幻觉。

新 prompt 要求**每个事实陈述紧跟来源编号**，格式为 `[来源:N]`。LLM 在生成每个句子时必须确认有对应 chunk 支撑，没有支撑的内容直接不写。

### 改动

**文件**: `prompts/rag/query.yaml`

修改前:
```yaml
1. 优先从参考资料中提取相关信息来回答，在答案末尾列出信息出处，格式为：
   📚 来源：[1] 文件名
2. 如果参考资料只能覆盖问题的部分内容，请就现有资料给出部分回答，
   并在末尾说明："注：以上回答基于现有资料，可能不完整。"
3. 禁止凭空编造。参考资料完全无关时才说"知识库中没有相关信息"。
```

修改后:
```yaml
1. 从参考资料中提取相关信息来回答。每个事实陈述后面标注来源编号，
   格式为 [来源:N]。示例：
   "雷志成是在红岸基地被叶文洁杀害的 [来源:1]。手段是锯断绳索 [来源:1]。"
   任何没有参考资料支撑的内容不得写入回答。
2. 如果参考资料只能覆盖问题的部分内容，就现有资料给出部分回答，
   格式与规则1相同。末尾说明："注：以上回答基于现有资料，可能不完整。"
3. 禁止凭空编造。参考资料完全无关时才说"知识库中没有相关信息"。
4. 回答末尾汇总来源：📚 来源：[1] 文件名, [2] 文件名
```

## P1: 置信度标记

### 原理

`max_dense`（向量搜索的最大余弦相似度）和是否触发深度搜索，综合反映了检索质量：

| max_dense | 含义 | 置信度 |
|:--|:--|:--|
| ≥ 0.70 | 向量搜索高置信命中，chunk 语义高度匹配 | 🟢 高 |
| < 0.70 且 ≥ 0.50 | 中等置信，或触发了深度搜索 | 🟡 中 |
| < 0.50（深度搜索）| 向量匹配差，即使深度搜索也有风险 | 🔴 低 |

### 后端改动

**文件**: `src/knowledge/query_engine.py`

`_retrieve()` 返回的 dict 中新增 `confidence` 字段：

```python
# 在 _retrieve() 返回前，根据检索质量计算置信度
if top_score >= 0.70:
    confidence = "high"
elif top_score >= 0.50 or deep_search_used:
    confidence = "medium"
else:
    confidence = "low"

return {
    "nodes": top_nodes,
    "sources": sources,
    "context": "\n\n".join(context_parts),
    "confidence": confidence,
}
```

`query_stream()` 在推送 sources 时附带 confidence：

```python
yield f"data: {json.dumps({'sources': [...], 'confidence': confidence})}\n\n"
```

### 前端改动

**文件**: `f:/AI/workspace/ai-assistant-web/src/views/ChatView.vue`

收到 SSE 事件时提取 `d.confidence`，在回答前显示标签：

```javascript
// 存储 confidence
let ragConfidence = 'medium'
if (d.confidence) ragConfidence = d.confidence

// 展示标签
const badgeMap = { high: '🟢 高置信度', medium: '🟡 中置信度', low: '🔴 低置信度' }
messages.value[ragIdx].confidence = badgeMap[ragConfidence] || ''
```

## 未来方向（P2 NLI 事实校验）

当前项目中 Reranker 已通过子进程隔离运行。BGE-Reranker-v2-m3 的 cross-encoder 架构天然支持 NLI 任务——判断"前提（chunk）是否蕴含假设（answer fragment）"。未来可以在 Reranker 子进程中增加一个 NLI 模式，对 LLM 答案逐句校验。

关键挑战：
1. NLI 需要不同的 prompt 格式（entailment vs relevance）
2. 逐句校验增加 N 次推理调用（N = 答案拆句数）
3. 阈值设定需要经验调优

### 不影响的功能

- 纯 LLM 对话（/chat）不受影响——置信度仅在 RAG 查询中返回
- 检索逻辑完全不变——只在返回值中增加了 confidence 字段
- 缓存键不变——confidence 不参与缓存计算，同一查询可复用缓存
