# 权限体系复盘：从"纸老虎"到"真守卫"

**日期**: 2026-06-06
**类型**: 权限与多租户优化

---

## 背景

项目实现了 RBAC 权限系统，但经过审计发现 5 个结构性问题：幽灵权限、角色扁平、使用限制缺失、文档级隔离缺失、管理者可见性不足。本次优化聚焦实际能解决的问题。

---

## 优化清单

### 1. 清理幽灵权限 — 删掉 `knowledge:manage`

**问题**: `knowledge:manage` 在 `editor` 和 `tenant_admin` 中定义，但系统没有对应的"管理知识库"功能。文档的增删本身就是知识库管理，`document:upload` + `document:delete` 已经覆盖。

**修改**:
- [src/api/permissions.py](../src/api/permissions.py): tenant_admin 和 editor 权限列表中删除 `knowledge:manage`

---

### 2. 补齐文档下载 — `document:download` 不再幽灵

**问题**: 权限矩阵定义了 `document:download`，但没有下载端点和前端按钮。

**修改**:
- [src/api/routes/documents.py](../src/api/routes/documents.py): 新增 `GET /{doc_id}/download`，权限 `require_permission("document:download")`，租户隔离校验，返回 `FileResponse`
- [src/views/DocumentsView.vue](../src/ai-assistant-web/src/views/DocumentsView.vue): 表格每行新增 📥 下载按钮（仅 editor+ 角色可见），fetch + Bearer token 方式下载

---

### 3. 会话路由加权限检查

**问题**: 5 个会话端点使用 `Depends(get_current_user)`，无权限保护。虽然所有角色都有 chat 权限，但风格不一致。

**修改**:
- [src/api/routes/sessions.py](../src/api/routes/sessions.py):
  - 创建/重命名/删除：`require_permission("chat:send")`
  - 列表/详情：`require_permission("chat:view")`

---

### 4. Viewer 去文档化

**问题**: viewer 拥有 `document:view`，能看到文档管理页面和所有租户文档列表。viewer 的定位应该是"普通用户，只能聊天和查询"。

**修改**:
- [src/api/permissions.py](../src/api/permissions.py): viewer 权限列表中删除 `document:view`
- [src/router/index.ts](../src/ai-assistant-web/src/router/index.ts): `/documents` 路由加 `role: ['super_admin', 'tenant_admin', 'editor']`

**效果**: viewer 登录后只能聊天页和查询，看不到文档管理入口，手动输 URL 也会被踢到 `/chat`。

---

### 5. 监控页加权限守卫

**问题**: `/monitoring` 页面前端路由仅要求登录，后端端点无任何权限检查。viewer 也能看 CPU、token 消耗、成本。

**修改**:
- [src/api/permissions.py](../src/api/permissions.py): tenant_admin 新增 `monitoring:view`（super_admin 已有 `*` 通配符）
- [src/monitoring/dashboard.py](../src/monitoring/dashboard.py): `GET /monitoring` 加 `Depends(require_permission("monitoring:view"))`
- [src/router/index.ts](../src/ai-assistant-web/src/router/index.ts): `/monitoring` 路由加 `role: ['super_admin', 'tenant_admin']`

---

### 6. JWT 密钥加固

**问题**: 默认密钥为公开字符串，`.env` 未覆盖时 Token 可被伪造。

**修改**:
- [.env](../.env): 新增 `JWT_SECRET=<随机 64 字符>`（通过 `secrets.token_hex(32)` 生成）

---

### 7. 父块查询补租户过滤（防御深度）

**问题**: `_fetch_parent_contexts()` 是唯一不查 `tenant_id` 的数据访问。子块已过滤，实际风险极低，但风格不一致。

**修改**:
- [src/knowledge/index_store.py](../src/knowledge/index_store.py): `_fetch_parent_contexts` 加 `tenant_id` 参数 + `WHERE tenant_id = %s`
- [src/knowledge/retrieval.py](../src/knowledge/retrieval.py): `_expand_to_parents` → `retrieve` → `retrieve_with_rerank` 全链透传 `tenant_id`

## 刻意不做的事项

| 问题 | 原因 |
|------|------|
| Viewer 使用频率限制 | 内网部署，网络层 IP 隔离已够用 |
| 文档级细粒度权限 | 当前规模一个租户全共享合理，等需求明确再上方案 B |
| 按租户/用户拆分的用量统计 | 监控页已有全局统计，分拆等付费客户上线再做 |
| `quality:view` 权限保留但无功能 | quality 模块待实现，权限预留合理 |
