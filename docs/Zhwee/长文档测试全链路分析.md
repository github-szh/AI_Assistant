## 逐步详解

### 第 1 步：前端预检重复 `POST /upload/check`

**代码**: [src/api/routes/upload.py:29-42](../src/api/routes/upload.py#L29)

```python
row = conn.execute(
    "SELECT doc_id, filename FROM t_document WHERE filename = %s AND file_size = %s",
    [req.filename, req.file_size],
).fetchone()
if row:
    return {"exists": True, ...}

```

前端在上传文件前先发一个轻量请求，按**文件名 + 文件大小**查 `t_document` 表。这里是粗略检查（不读文件内容），返回「不存在」，前端开始真正上传文件。

**为什么要有这一步**：避免用户把同一个文件上传两遍才发现重复，提前拦截节省带宽和时间。

### 第 3 步：读取文件二进制内容 + 计算 MD5

**代码**: [src/api/routes/upload.py:236-238](../src/api/routes/upload.py#L236)


**为什么用 MD5**：文件名和大小可以变，但 MD5 是文件内容的指纹。同一份 PDF 改名后上传，MD5 相同就能识别为重复。

**代码**: [src/api/routes/upload.py:239-248](../src/api/routes/upload.py#L239)

### 第 8 步：OCR 检测 `guess_need_ocr()`

**代码**: [src/parsing/loader.py:102-129](../src/parsing/loader.py#L102)

```python
def guess_need_ocr(self, file_path):
    doc = fitz.open(str(file_path))
    pages_to_check = min(3, len(doc))     # 只查前 3 页
    for i in range(pages_to_check):
        text = doc[i].get_text().strip()  # 用 PyMuPDF 提取每页文本
        cjk_chars = sum(1 for c in text if '一' <= c <= '鿿')
        if cjk_chars >= 10:              # 任意一页有 ≥10 个中文字
            return False                  # → 原生 PDF，不需要 OCR
    return True                           # → 无中文，走 OCR
```

**核心思路**：扫描件 PDF 里的"文本"其实是 OCR 伪影（零散数字符号），不会有真正的中文句子。所以用「前 3 页是否有 ≥10 个 CJK 字符」判断。**本文档前 3 页有中文 → 返回 False → 走 PyMuPDF**。

### 第 12 步：正式切块（带 Sentence Window）

**代码**: [src/api/routes/upload.py:339-349](../src/api/routes/upload.py#L339)

```python
chunker = Chunker(strategy="fixed_size", sentence_window=True)  # SW 已自动启用
if chunker.sentence_window:
    result = chunker.chunk_with_windows(parsed)        # SW 模式
    chunks = result.index_chunks
    ingest_documents(
        result.index_chunks,                            # 子块（给向量搜索用）
        parent_docs=result.context_chunks,              # 父块（给 LLM 上下文用）
        child_to_parent=result.index_to_parent,         # 映射关系
    )
```

但这里的 `strategy=fixed_size` 不支持 Sentence Window（只有 `sentence` / `recursive` 支持），所以 `chunk_with_windows()` 内部降级：

**代码**: [src/parsing/chunker.py:76-85](../src/parsing/chunker.py#L76)

```python
def chunk_with_windows(self, docs):
    if self.strategy not in ("sentence", "recursive"):
        flat = self.chunk(docs)                           # 降级为普通切块
        return ChunkResult(
            index_chunks=flat,                            # 子块 = 23 块
            context_chunks=flat,                          # 父块 = 同一批 23 块
            index_to_parent={i: i for i in range(len(flat))}  # 1:1 映射
        )
```

**日志**:
```
切割完成: 17页 → 23块, 策略=fixed_size (0.00s)     ← chunk() 输出
切割完成(无窗口): 17页 → 23块 (0.00s)               ← 降级提示
```

**注意**：这里有一个设计上的小问题 — SW 被自动启用了但 `fixed_size` 策略不支持，导致子块和父块完全相同。后续检索时 Sentence Window 展开不会扩大上下文（因为没有更大的父块）。如果有意使用 SW，应该用 `sentence` 或 `recursive` 策略。

23 个文本 → 23 个 **1024 维向量**，耗时约 2 秒。智谱 embedding-3 的维度是 1024。

**为什么是 1024 维**：向量维度决定了相似度计算的精度和存储成本。1024 维是 embedding-3 标准输出，足够区分语义但不会过大。

### 第 15 步：BM25 分词替换

**代码**: [src/knowledge/ingestion.py:66-69](../src/knowledge/ingestion.py#L66)

```python
for node in nodes:
    node.metadata["original_text"] = node.text   # 保存原始中文文本
    node.set_content(tokenize(node.text))         # 替换为 jieba 分词结果
```

每个 node 做了**双存储**：

| 位置 | 内容 | 用途 |
|------|------|------|
| `node.metadata["original_text"]` | 原始中文文本 | 检索后给 LLM 和 reranker 阅读 |
| `node.text`（即 `data_documents.text`） | jieba 空格分词 | PostgreSQL `ts_vector` 全文索引，给 BM25 搜索用 |

**为什么分词**：PostgreSQL 的 `to_tsvector('simple', text)` 对中文无效（中文没有空格分词），所以要先 jieba 分词后再存入，BM25 才能正确匹配中文关键词。
