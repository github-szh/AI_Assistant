### Bug 1：Super admin 无法下载文档

**文件：** `src/api/routes/documents.py`（`download_document` 函数）

**问题：** `WHERE doc_id = %s AND tenant_id = %s` 无 super_admin 旁路，tenant_id=NULL 导致 SQL 永远不匹配，返回 404。

**修改：** 加 `is_super` 判断，与同文件的 `_query_pg_documents` 和 `delete_document.py` 对齐。

```python
    "SELECT filename, file_type FROM t_document WHERE doc_id = %s AND tenant_id = %s",
    [doc_id, tenant_id],

# 改后
is_super = user.get("role") == "super_admin"
tenant_id = user.get("tenant_id")
if is_super:
    row = conn.execute(
        "SELECT filename, file_type FROM t_document WHERE doc_id = %s", [doc_id],
    ).fetchone()
else:
    row = conn.execute(
        "SELECT filename, file_type FROM t_document WHERE doc_id = %s AND tenant_id = %s",
        [doc_id, tenant_id],
    ).fetchone()
```

### 问题 4：Super admin 上传文档 tenant_id=NULL

**问题：** admin 的 `t_user.tenant_id = NULL`，上传文档时 `t_document.tenant_id = NULL`，导致其他用户无法查看和搜索这些文档。若 admin 被降级，文档变孤儿。

**解决方案：** 采用方案 2——将 admin 的 tenant_id 设置为默认租户（id=1），跨租户能力靠 `role == "super_admin"` 判断。

**数据库修改：**
```sql
UPDATE t_user SET tenant_id = 1 WHERE username = 'admin' AND tenant_id IS NULL;
UPDATE t_document SET tenant_id = 1 WHERE tenant_id IS NULL;
UPDATE t_session_info SET tenant_id = 1 WHERE tenant_id IS NULL;
UPDATE data_documents SET metadata_ = jsonb_set(metadata_::jsonb, '{tenant_id}', '"1"'::jsonb)::json
    WHERE COALESCE(metadata_->>'tenant_id', '') IN ('', 'None') OR metadata_->>'tenant_id' IS NULL;
```

修复结果：
- t_user：1 行（admin）
- t_document：4 行
- data_documents：504 行

## Windows reload 后无法重启

> 日期：2026-06-07

### 根因

uvicorn `--reload` 在 Windows 上终止旧 worker 进程后，`RotatingFileHandler` 持有的日志文件句柄未释放。新进程启动时 `setup_logging()` 再打开同一文件失败，进程直接崩溃。

### 修复

**文件：** `src/observability/logging_config.py`

- 保存 `_file_handler` 模块级引用
- 新增 `shutdown_logging()` 函数：从 root/uvicorn logger 移除 handler 并调用 `close()` 释放 Windows 文件句柄

**文件：** `src/api/main.py`

- lifespan shutdown 中 `close_pool()` 之后调用 `shutdown_logging()`

### 附带优化

**文件：** `src/api/deps.py`

- `_Pool.close()`：每个连接先 `rollback()` + `autocommit=True` 再 `close()`，避免事务状态阻塞关闭
- `close_pool()`：`asyncio.wait_for(timeout=5)` 包裹，防止卡死 shutdown

## SW 展开丢弃无 parent_id 的 chunk

> 日期：2026-06-07

### 根因

`sentence_window` 模式（大文档自动启用）给 chunk 加了 `parent_id`，小文档没有。检索时两类 chunk 混在一起，`_expand_to_parents()` 收集到 `parent_id` 后进入"展开模式"，在第二轮循环中：`if not pid or pid in emitted: continue` — 没有 `parent_id` 的 chunk 被直接跳过。

### 修复

**文件：** `src/knowledge/retrieval.py`（`_expand_to_parents` 第 167-174 行）

三个分支独立处理：

- `not pid` → `result.append(node)` 原样保留
- `pid in emitted` → 去重跳过
- 正常展开 → 用 parent 内容替换；若 parent 查不到 → 回退保留原始 child

## 从 Chat 流程移除 QualityGuard，保留 RAG测评

> 日期：2026-06-07

### 背景

QualityGuard 在 Chat 流程中自动触发，每次 RAG 查询额外调用 3 次 LLM Judge（Safety + Factuality + Relevance），带来 ~10s 延迟和额外 API 费用。但生产实践中：

- 安全关键词过滤器已禁用（误杀法律文本），safety 仅走 LLM 语义评判
- 检索质量检查器因 BGE 归一化阈值已降到 0.1，形同虚设
- 99% 的回答显示"质检通过"，成本和延迟换来的价值极低
- RAG测评页面（`/eval`）已覆盖 Chat 质检全部能力，还多了 `ground_truth` + `answer_correctness`

### 决策

Chat 流程不再自动跑质检，RAG测评页面作为主动调试工具保留。

### 关键约束

## RAG测评 query_eval 异步调用 bug

> 日期：2026-06-07

### 现象

RAG测评页面报错 `TypeError: 'coroutine' object is not subscriptable`。

### 根因

`query_eval()` 是同步方法（`def`），但内部调用了异步方法 `self._retrieve()`（`async def`），没有 `await`，返回的是 coroutine 对象而非 dict。后续 `result["nodes"]` 对 coroutine 做下标访问触发 TypeError。

这是已有 bug，非本次 QualityGuard 移除引入。

### 修复

**文件：** `src/knowledge/query_engine.py`

```python
# 改前
def query_eval(self, ...):
    result = self._retrieve(...)

# 改后
async def query_eval(self, ...):
    result = await self._retrieve(...)
```

**文件：** `src/api/routes/query.py`

```python
# 改前
eval_result = engine.query_eval(...)

# 改后
eval_result = await engine.query_eval(...)
```

## QualityGuard Judge 模型未使用配置的 flash 版本

> 日期：2026-06-07

### 现象

日志显示质检调用的是 `deepseek-v4-pro`，但 `.env` 配置了 `QUALITY_JUDGE_MODEL=deepseek/deepseek-v4-flash`。

### 根因

`get_query_engine()` 创建所有 checker 时**没传 config**，各 checker 的 `self.config` 为空字典 `{}`：

```python
# 改前
ragas_faithfulness = RagasFaithfulness(llm_provider=llm)        # config={}
ragas_correctness = RagasFactualCorrectness(llm_provider=llm, weight=0.5)  # config={}
# ...
"safety": SafetyChecker(llm_provider=llm),                       # config={}
```

导致两处 LLM 调用无法读取 `quality_judge_model`：

1. `SafetyChecker._do_llm_call()`（base.py:177-178）— `self.config.get("quality_judge_model", "")` 返回空字符串，不传 model 走默认
2. `_decompose_claims()`（ragas_checker.py:39）— 独立函数无 config 访问能力，直接调用 `llm_provider.chat()` 不传 model

### 修复

**文件：** `src/quality/ragas_checker.py`

`_decompose_claims()` 加 `model` 参数：

```python
# 改前
def _decompose_claims(llm_provider: Any, text: str) -> list[str]:
    response = llm_provider.chat(
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0, max_tokens=512,
    )

# 改后
def _decompose_claims(llm_provider: Any, text: str, model: str = "") -> list[str]:
    call_kwargs = dict(messages=[...], temperature=0.0, max_tokens=512)
    if model:
        call_kwargs["model"] = model
    response = llm_provider.chat(**call_kwargs)
```

`RagasFactualCorrectness.evaluate()` 和 `RagasFaithfulness.evaluate()` — 从 config 取 model 传入：

```python
judge_model = self.config.get("quality_judge_model", "")
answer_claims = _decompose_claims(self.llm_provider, answer, model=judge_model)
```

**文件：** `src/knowledge/query_engine.py`

`get_query_engine()` 注入 judge 配置到各 checker：

```python
ragas_judge_config = {
    "quality_judge_model": settings.quality_judge_model,
    "quality_judge_provider": settings.quality_judge_provider,
}
ragas_faithfulness = RagasFaithfulness(llm_provider=llm, config=ragas_judge_config)
ragas_correctness = RagasFactualCorrectness(llm_provider=llm, config=ragas_judge_config, weight=0.5)

checkers = {
    "safety": SafetyChecker(llm_provider=llm, config={
        "quality_judge_model": settings.quality_judge_model,
        "quality_judge_provider": settings.quality_judge_provider,
        "quality_judge_timeout_s": settings.quality_judge_timeout_s,
        "quality_fail_closed_for_safety": settings.quality_fail_closed_for_safety,
        "prompts_dir": settings.prompts_dir,
    }),
    ...
}
```
