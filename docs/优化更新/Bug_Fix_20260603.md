# Bug Fix: RAG 搜索偶发性不走知识库，LLM 直接回答

**日期**: 2026-06-03  
**严重程度**: 高  
**影响范围**: 前端 ChatView 知识库搜索  

---

## 现象

用户在聊天窗口搜索"叶文洁是谁？"，RAG 开关已开启，但回答由 LLM 直接从训练数据生成，没有走知识库检索流程，回答不带来源标注。

## 根因

`sources` SSE 事件约 2693 字节，被网络 TCP 分块传输（每块 ~1024 字节）。前端 `fetch + ReadableStream` 的 SSE 解析器每次 `read()` 后按 `\n` 独立切分行，没有跨 chunk 拼接机制：

- 第 1 块：`data: {"sources": [{"doc_id":"f672` → JSON 不完整，`JSON.parse()` 失败，被空 catch 静默丢弃
- 第 2 块：`...RF融合 → 5条候选"...她是文革...` → 不以 `data:` 开头，被跳过
- 第 3 块：`...家..."}], "confidence":"medium"}` → 同样不以 `data:` 开头，被跳过

`ragUsed` 变量永远保持 `false`，`{"done": true}` 到达时前端判定 RAG 失败，触发 `/api/chat/stream` 兜底。

日志证据：

```
23:22:07  POST /query/stream → 200 (0.632s)    ← RAG 成功返回 3 条来源
23:22:10  POST /chat/stream  → 200 (1.186s)    ← 前端误判，走了 LLM 兜底
```

## 涉及文件

| 文件 | 角色 |
|------|------|
| `ai-assistant-web/src/views/ChatView.vue:210` | 前端 SSE 解析（根因所在） |
| `src/knowledge/query_engine.py:290` | 后端 SSE 事件发送 |

## 修复方案

两层防御，互为保证。

### 第一层（修复根因）：前端加 SSE 行缓冲区

**ChatView.vue** — 参照 OpenAI / Anthropic SDK 的 `LineDecoder` 实现，在 SSE 读取循环中加入 `lineBuffer`：

```javascript
// 修复前
for (const line of dec.decode(value).split('\n')) {

// 修复后
let lineBuffer = ''
while (true) {
    const { done, value } = await ragReader.read()
    if (done) break
    const text = lineBuffer + dec.decode(value, { stream: true })  // 拼上轮残留
    const lines = text.split('\n')
    lineBuffer = text.endsWith('\n') ? '' : (lines.pop() || '')     // 残行留到下轮
    for (const line of lines) {
        // ...
    }
}
```

核心模式 `split + pop`：
1. 上轮残留的 `lineBuffer` + 本轮 chunk → 拼接完整文本
2. 按 `\n` 切分 → `pop()` 取走最后不完整的行暂存
3. `{ stream: true }` 确保多字节 UTF-8 字符不被截断

### 第二层（防御加固）：后端发轻量状态信号

**query_engine.py** — 在大体积 `sources` 事件之前，先发一个 19 字节的信号事件：

```python
yield f"data: {json.dumps({'status': 'found'})}\n\n"
yield f"data: {json.dumps({'sources': [...]})}\n\n"
```

**ChatView.vue** — 前端处理此信号：

```javascript
if (d.status === 'found') {
    ragUsed = true
}
```

`status` 事件只有 19 字节，不可能跨 TCP chunk，百分百可靠。即使第一层失效，这一层也能独立解决 bug。

## 业界依据

此模式是 SSE 客户端解析的行业标准，三大 SDK 均采用相同实现：

| SDK | 核心类 | 模式 |
|-----|--------|------|
| OpenAI Python | `SSEDecoder._data` | accumulate → flush on `\n\n` |
| Anthropic TypeScript | `LineDecoder.buffer` | `split('\n') + pop()` + `{ stream: true }` |
| sse-frame (Rust) | `Parser.push()` | push bytes → buffer → emit on `\n\n` |

## 验证

1. 后端直接执行验证：`status` 事件（19 字节）在 `sources`（2693 字节）之前发出，顺序正确
2. 线上验证：重启服务后搜索"叶文洁是谁？"，回答带有 `label: 'rag'` 和来源标注，`/chat/stream` 不再被误调
