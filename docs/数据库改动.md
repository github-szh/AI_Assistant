## 新增表

### 1. chunk_contexts — Sentence Window 父 chunk 存储

**功能**: 长文档 Embedding（Sentence Window Retrieval）

**说明**: 子 chunk（3 句/组）存入向量库做精准检索，父 chunk（15 句/组）存入此表。检索命中子 chunk 后，通过 `parent_id` 反查父 chunk，将完整段落喂给 LLM，实现上下文 5.2 倍扩展。

**代码位置**: `src/knowledge/index_store.py:130-155`

```sql
CREATE TABLE IF NOT EXISTS chunk_contexts (
    parent_id   TEXT PRIMARY KEY,       -- 格式: "{doc_id}:{parent_index}"
    doc_id      TEXT NOT NULL,          -- 所属文档 ID
    content     TEXT NOT NULL,          -- 父 chunk 原文（非分词，直接喂 LLM）
    filename    TEXT,                   -- 源文件名
    chunk_index INTEGER                 -- 父 chunk 序号
);

CREATE INDEX IF NOT EXISTS idx_chunk_contexts_doc_id
    ON chunk_contexts (doc_id);
```

**写入方式**: `_insert_parent_contexts()` — 上传文档时批量 INSERT（`ON CONFLICT DO NOTHING`）

**查询方式**: `_fetch_parent_contexts()` — `SELECT ... WHERE parent_id = ANY($1)`，检索展开时调用

---

### 2. doc_summaries — 文档摘要向量索引

**功能**: 两级检索（Level 1 摘要搜索）

**说明**: 上传文档时 AI 自动生成 5-8 句中文摘要，embed 后存入此表。查询时先搜摘要定位 top-3 相关文档（Level 1），再在这 3 篇文档内搜 chunk（Level 2），将候选范围从全库收窄到目标文档。

**代码位置**: `src/knowledge/index_store.py:210-233`

```sql
CREATE EXTENSION IF NOT EXISTS vector;  -- 确保 pgvector 扩展已启用

CREATE TABLE IF NOT EXISTS doc_summaries (
    doc_id      TEXT PRIMARY KEY,       -- 文档 ID
    summary     TEXT NOT NULL,          -- AI 生成的摘要（5-8 句中文）
    embedding   vector(1024),           -- 摘要的向量嵌入（Zhipu embedding-3, 1024维）
    filename    TEXT,                   -- 源文件名
    chunk_count INTEGER,                -- chunk 总数
    created_at  TIMESTAMP DEFAULT NOW()
);
```

**写入方式**: `_insert_summary()` — 上传文档时 UPSERT（`ON CONFLICT DO UPDATE`）

**查询方式**: `_search_summaries()` — `SELECT ... ORDER BY embedding <=> $1::vector LIMIT $2`，余弦距离排序

## 已有表新增字段

### 3. t_session_info — 新增 summary 字段

**功能**: 上下文管理（会话摘要）

**迁移脚本**: `scripts/V20260528.01__storage_optimization.sql`

```sql
ALTER TABLE t_session_info ADD COLUMN IF NOT EXISTS summary TEXT;
```

**说明**: 存储会话的滚动摘要。当 `t_session_message` 中未摘要的用户消息超过 200 条时，LLM 将最旧的（总数 - 20）条消息合并生成 300 字中文摘要，存入此字段。后续对话中摘要被注入到 system prompt 的 `[对话历史摘要]` 段。

---

### 4. t_session_message — 新增 summarized 字段

**功能**: 上下文管理（消息摘要标记）

**迁移脚本**: `scripts/V20260528.01__storage_optimization.sql`

```sql
ALTER TABLE t_session_message ADD COLUMN IF NOT EXISTS summarized BOOLEAN DEFAULT FALSE;
```

**说明**: 标记该消息是否已被纳入会话摘要。摘要生成后将相关消息的此字段设为 `true`，避免重复摘要。

## 已有表（含本次项目字段）

### t_document — 文档元数据表

**功能**: 文档元数据存储（摘要、去重、统计）

**迁移脚本**: `scripts/V20260522.01__create_t_document.sql`

```sql
CREATE TABLE IF NOT EXISTS t_document (
    id            SERIAL PRIMARY KEY,
    doc_id        VARCHAR(12) UNIQUE NOT NULL,   -- 文档唯一标识
    filename      VARCHAR(500),                  -- 文件名
    file_type     VARCHAR(20),                   -- 文件类型 (.pdf/.txt/.docx)
    file_size     BIGINT,                        -- 文件大小（字节）
    pages         INT,                           -- 页数
    parser_used   VARCHAR(50),                   -- 解析器名称
    chunks_count  INT,                           -- chunk 总数
    summary       TEXT,                          -- AI 生成的文档摘要
    md5_hash      VARCHAR(32) UNIQUE,            -- MD5 去重哈希
    uploaded_at   TIMESTAMPTZ DEFAULT NOW(),     -- 上传时间
    user_id       INT                            -- 上传用户 ID
);
```

**关键字段说明**:
- `summary`: 上传时 AI 自动生成（LLM 调用），用于前端文档预览 + 两级检索 Level 1
- `md5_hash`: 文件内容 MD5，上传去重（相同文件返回 `status=duplicate`）
