# 历史会话不显示问题修复说明

| 项目 | 内容 |
|---|---|
| 日期 | 2026-06-02 |
| 修改人员 | AI Assistant 开发团队 |
| 涉及模块 | `sessions.py`、`query_engine.py`、`ChatView.vue` |

---

## 一、问题现象

1. **历史会话不在侧边栏显示**：用户完成对话后，刷新页面或重新登录，侧边栏中的会话列表为空，或显示的会话没有消息内容。
2. **通用问题触发 RAG**：如"请做自我介绍"等通用对话，系统先去检索知识库，返回"知识库中没有找到相关信息"，而非直接由 LLM 回答。

---

## 二、根因分析

### 2.1 RAG `not_found` 路径的空消息泄漏

`ChatView.vue` 的 `send()` 函数中，当 RAG 开关开启时，无论是否有结果，都会在 `messages` 数组中推入一条空的 assistant 消息：

```
send() 被调用
  └→ messages.value.push({ role: 'assistant', content: '' })     // 推入空消息
  └→ SSE 流收到 {"step": "not_found"}
  └→ 原始代码仅 break，未 pop 空消息
  └→ LLM 兜底路径推入第二条 assistant 消息
  └→ messages 数组状态: [user_msg, empty_assistant, real_assistant]
```

**结果**：空消息在 UI 中渲染为空白气泡，让用户误以为会话异常。

### 2.2 `/chat` 保存失败被静默吞掉

```javascript
// 原始代码
try { api.post('/chat', { ... }) } catch {}    // 空 catch，错误被忽略
```

当数据库连接超时、网络异常等导致消息保存失败时，错误被静默忽略。会话虽已创建（`POST /sessions`），但 `t_session_message` 表中无记录，侧边栏显示空会话。

### 2.3 会话排序异常

`t_session_info` 表在创建会话时 `updated_at` 为 NULL，查询使用 `ORDER BY s.updated_at DESC`，新会话排在列表末尾，用户不易发现。

### 2.4 缺乏意图分类机制

系统没有区分"知识问答"和"通用对话"的逻辑，所有问题默认走 RAG 优先策略。当知识库为空时，每次请求都触发 RAG → `not_found` → LLM 兜底的冗余流程。

---

## 三、修改方案

### 3.1 修复 `not_found` 路径的空消息泄漏

**文件**：`ChatView.vue`

```javascript
// 第 265-271 行
if (d.step === 'not_found' || d.error) {
  if (ragIdx >= 0 && messages.value[ragIdx]?.role === 'assistant' && !messages.value[ragIdx].content) {
    messages.value.pop()          // 弹出第 202 行推入的空消息
  }
  ragIdx = -1                     // 重置索引，防止后续误操作
  break
}
```

**说明**：收到 `not_found` 事件时，检查 `ragIdx` 指向的 assistant 消息内容是否为空，若是则弹出，确保 `messages` 数组不残留空白气泡。

### 3.2 LLM 兜底前更新 thinking 状态

**文件**：`ChatView.vue`

```javascript
// 第 283 行
if (!ragUsed) {
  thinking.value = '💬 正在通过AI生成回答...'   // 明确告知用户系统已切换
```

**说明**：进入 LLM 兜底路径时立即更新状态文本，用户不会卡在"正在搜索知识库…"的提示上。

### 3.3 知识库空检测 & RAG 开关自动禁用

**文件**：`ChatView.vue`

```javascript
// 第 95 行 — 新增状态
const kbEmpty = ref(false)

// 第 116-125 行 — 检测函数
async function checkKbStatus() {
  try {
    const r = await api.get('/documents')
    const total = r.data.total || 0
    kbEmpty.value = total === 0
    if (kbEmpty.value) ragEnabled.value = false  // KB 为空时自动关闭 RAG
  } catch {
    kbEmpty.value = false
  }
}

// 第 366 行 — 挂载时调用
onMounted(() => { loadSessions(); checkKbStatus() })
```

```html
<!-- 第 22-25 行 — 模板 -->
<div class="rag-toggle"
     @click.stop="kbEmpty ? null : ragEnabled=!ragEnabled"
     :class="{on:ragEnabled, disabled:kbEmpty}"
     :title="kbEmpty ? '知识库为空，自动切换为通用模式' : ''">
  <span class="rag-toggle-knob" />
  <span class="rag-label">{{ kbEmpty ? '🤖 通用（知识库为空）' : ragEnabled ? '📚 知识库' : '🤖 通用' }}</span>
</div>
```

### 3.4 `/chat` 保存失败不静默

**文件**：`ChatView.vue`

```javascript
// 第 318-320 行
try { await api.post('/chat', { messages: ..., session_id: currentId.value }) } catch (e: any) {
  console.warn('会话保存失败:', e)
}
```

**说明**：保存失败时输出警告日志到控制台，便于排查问题。

### 3.5 修复会话创建时的时间戳

**文件**：`sessions.py`

```python
# 第 29-31 行
conn.execute(
    "INSERT INTO t_session_info (id, title, user_id, created_at, updated_at) VALUES (%s,%s,%s,NOW(),NOW())",
    [sid, "新对话", user["user_id"]],
)
```

**说明**：创建会话时同时写入 `created_at` 和 `updated_at`，确保排序字段不为 NULL。

### 3.6 修复会话排序

**文件**：`sessions.py`

```python
# 第 42-44 行
"""SELECT s.id, s.title, s.created_at, s.updated_at,
          (SELECT count(*) FROM t_session_message m WHERE m.session_id=s.id) as msg_count
   FROM t_session_info s WHERE s.user_id=%s ORDER BY COALESCE(s.updated_at, s.created_at) DESC"""
```

**说明**：使用 `COALESCE` 在 `updated_at` 为 NULL 时降级为 `created_at`，确保会话始终按正确顺序排列。

### 3.7 RAG 置信度过低时触发 LLM 兜底

**文件**：`query_engine.py`

```python
# 第 187-190 行
if confidence == "low" and top_score < 0.40:
    logger.info("置信度过低(%.3f<0.40)，触发 LLM 兜底", top_score)
    return {"nodes": [], "sources": [], "context": "", "confidence": "low"}
```

**说明**：RAG 检索结果的最高相似度低于 0.40 时，视为无相关内容，返回空结果触发 LLM 兜底，避免用无关文档片段生成错误答案。

### 3.8 `not_found` SSE 事件携带 confidence

**文件**：`query_engine.py`

```python
# 第 253-254 行
confidence = result.get("confidence", "low")
yield f"data: {json.dumps({'step': 'not_found', 'msg': '知识库中没有找到相关信息。请先上传相关文档。', 'confidence': confidence})}\n\n"
```

**说明**：`not_found` 事件增加 `confidence` 字段，为前端后续可能的置信度展示或逻辑分支提供数据。

## 六、验证方式

1. **新会话创建**：登录后发送消息，侧边栏应实时显示该会话，标题为消息前 10 字
2. **通用问题**：提问"请做自我介绍"，系统应直接由 LLM 回答，不先显示知识库搜索
3. **知识库空场景**：未上传文档时，RAG 开关应自动变为"通用（知识库为空）"且不可切换
4. **会话排序**：最近有活动的会话应在列表顶部
5. **刷新后恢复**：页面刷新后，所有历史会话应在侧边栏完整显示
